1. OpenAI, 고위험 사용자용 Advanced Account Security 도입

핵심 요약

OpenAI는 4월 30일 ChatGPT 계정용 opt-in 보안 모드인 Advanced Account Security를 공개했습니다. 이 모드를 켜면 비밀번호 기반 로그인이 비활성화되고 패스키 또는 물리 보안키 기반 로그인으로 전환됩니다. 계정 복구 역시 이메일·SMS 대신 백업 패스키, 보안키, 복구키 같은 강한 수단만 허용됩니다. OpenAI는 로그인 알림, 더 짧은 세션, 활성 세션 관리 강화와 함께 해당 보호가 Codex까지 확장된다고 설명했습니다.

배경·업계 영향

이제 AI 계정에는 단순 대화 기록을 넘어 코드, 문서, 연결 앱, 업무 맥락이 쌓이기 때문에 계정 탈취의 피해 범위가 크게 커졌습니다. OpenAI가 언론인, 연구자, 공직자 같은 고위험군을 직접 언급한 점은 생성형 AI가 민감 업무 인프라로 깊게 들어왔다는 의미입니다. 앞으로 주요 AI 서비스에서 피싱 저항형 인증이 사실상 기본 기대치가 될 가능성이 큽니다.

왜 중요한지: AI 서비스의 신뢰 경쟁은 모델 성능만이 아니라 계정 보안 수준까지 포함하는 단계로 넘어갔습니다.

2. Google Cloud Next ’26, “에이전트 운영 플랫폼”과 8세대 TPU 전면화

핵심 요약

구글은 Cloud Next ’26에서 Gemini Enterprise Agent Platform과 8세대 TPU 전략을 핵심 축으로 제시했습니다. Sundar Pichai는 고객 직접 API 사용량이 분당 160억 토큰을 넘었고, 기업의 관심이 “에이전트를 만들 수 있나”에서 “수천 개 에이전트를 어떻게 관리하나”로 이동했다고 설명했습니다. 이에 맞춰 구글은 보안·거버넌스·확장을 함께 묶은 에이전트 운영 계층을 강조했습니다. 인프라 측면에선 학습용 TPU 8t와 추론용 TPU 8i를 분리한 듀얼 칩 접근을 발표하며 대규모 에이전트 워크로드 대응을 전면에 세웠습니다.

배경·업계 영향

기업 AI 시장은 이제 단일 모델 도입보다, 많은 에이전트를 운영 가능한 형태로 배치하고 감시하는 문제로 옮겨가고 있습니다. 구글 발표는 모델·보안·칩·운영도구를 한 번에 묶어 제공하려는 하이퍼스케일러 경쟁이 더 치열해졌다는 신호입니다. 특히 추론 전용 TPU를 별도로 내세운 점은 에이전트 시대에 inference economics가 핵심이라는 판단을 보여줍니다.

왜 중요한지: 앞으로 기업 AI 승부는 “좋은 모델 1개”보다 “대규모 에이전트 시스템을 굴리는 전체 스택”에서 갈릴 가능성이 큽니다.

Google, Cloud Next ‘26: Momentum and innovation at Google scale

3. Anthropic, Claude를 크리에이티브 툴체인 안으로 직접 연결

핵심 요약

Anthropic은 4월 28일 Claude for Creative Work를 발표하며 여러 크리에이티브 툴용 커넥터를 공개했습니다. 발표에 따르면 Adobe Creative Cloud, Ableton, Autodesk Fusion, Blender, SketchUp, Splice 등과 연결해 Claude가 문서 기반 튜터, 반복 작업 자동화, 툴 간 파이프라인 연결, 스크립트 작성 역할을 수행할 수 있습니다. Anthropic은 특히 Blender용 MCP 커넥터를 공식 제공하며 자연어로 Python API를 활용하도록 지원한다고 설명했습니다. 또한 Claude Design 결과물을 다른 툴로 넘기는 흐름도 강조했습니다.

배경·업계 영향

생성형 AI가 범용 채팅에서 실제 업계 소프트웨어 안으로 들어가는 전형적인 사례입니다. 크리에이티브 업계는 결과물 품질뿐 아니라 기존 툴체인과의 호환성이 중요한데, Anthropic은 그 지점을 정면으로 공략했습니다. AI가 사람을 완전히 대체하기보다는 기존 전문가의 생산성을 넓히는 방향으로 자리 잡고 있다는 점도 다시 확인됩니다.

왜 중요한지: AI의 실사용 가치는 독립형 챗봇보다 현업 도구 속 워크플로에 얼마나 자연스럽게 녹아드느냐에서 커집니다.

Anthropic, Claude for Creative Work

4. GitHub Copilot, 6월부터 usage-based billing으로 전환

핵심 요약

GitHub는 6월 1일부터 모든 Copilot 플랜을 GitHub AI Credits 기반 usage-based billing으로 전환한다고 밝혔습니다. 기존 premium request 방식 대신 입력·출력·캐시 토큰 사용량에 따라 크레딧이 차감되며, 기본 구독료는 유지됩니다. GitHub는 5월 초부터 예상 비용을 미리 볼 수 있는 청구 미리보기 경험도 제공한다고 설명했습니다. 배경으로는 장시간 에이전트형 코딩 세션 증가로 기존 정액성 구조가 지속 가능하지 않았다는 점을 분명히 들었습니다.

배경·업계 영향

AI 코딩 도구가 단문 추천에서 장시간 자율 작업으로 이동할수록 공급자 비용 구조는 급격히 무거워집니다. GitHub의 전환은 다른 개발자 AI 업체에도 가격 재설계 압박을 줄 가능성이 큽니다. 기업 입장에서는 기능 비교뿐 아니라 팀별 예산 통제와 모델 사용량 가시성이 더 중요한 관리 항목이 될 것입니다.

왜 중요한지: 에이전트형 코딩 시대에는 기능 경쟁만큼 과금 모델과 비용 통제가 제품 경쟁력의 일부가 됩니다.

5. GitHub, 최근 장애 이후 가용성 우선 전략과 30배 스케일 계획 공개

핵심 요약

GitHub CTO Vlad Fedorov는 최근 두 차례 장애 이후 가용성 개선 계획을 공개했습니다. 회사는 2025년 10월부터 10배 용량 확대 계획을 실행해왔지만, 2026년 2월에는 이미 현재 대비 30배 규모를 염두에 둔 설계가 필요하다고 판단했다고 밝혔습니다. 배경에는 agentic development 확산으로 저장소 생성, PR 활동, API 사용, 자동화, 대형 저장소 부하가 급증한 점이 있습니다. GitHub는 중요 서비스 격리, 캐시 및 인증 경로 개선, Go 이전 가속, 장기적으로 멀티클라우드 방향을 추진 중이라고 설명했습니다.

배경·업계 영향

개발 플랫폼도 이제 인간 개발자만을 위한 트래픽이 아니라 에이전트와 자동화가 대량 생성하는 워크로드를 견뎌야 합니다. GitHub의 이번 설명은 AI 시대 인프라 운영의 핵심 문제가 기능 추가보다 시스템 분리, 장애 반경 축소, 검색·큐·캐시 병목 제거에 있음을 잘 보여줍니다. 개발 도구 업계 전반에서도 안정성과 확장성 투자가 더 앞자리에 설 가능성이 큽니다.

왜 중요한지: 에이전트가 개발 플랫폼의 주된 사용자로 떠오르면서, 플랫폼 설계 자체가 새 스케일 전제에 맞춰 재편되고 있습니다.
