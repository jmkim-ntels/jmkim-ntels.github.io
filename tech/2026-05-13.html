1. Google Cloud Next 2026, 기업용 AI를 ‘에이전트 플랫폼’ 중심으로 재정렬

핵심 요약

Google은 Cloud Next 2026에서 Gemini Enterprise Agent Platform, 차세대 TPU, 데이터·네트워크 인프라, Workspace 연계를 한꺼번에 묶은 대규모 업데이트를 다시 강조했습니다. 발표에 따르면 Google Cloud 고객의 약 75%가 이미 AI 제품을 사용 중이며, 330개 고객이 지난 12개월 동안 각자 1조 토큰 이상을 처리했습니다. Google은 직접 API 경로를 통한 고객 처리량이 분당 160억 토큰을 넘었다고 밝혔습니다. 핵심 메시지는 ‘모델 접근’이 아니라 실제 기업 워크플로를 에이전트 중심으로 전환하는 운영 체계를 제공하겠다는 것입니다.

배경·업계 영향

이 발표는 하이퍼스케일러 간 경쟁이 개별 모델 성능 비교를 넘어, 누가 더 넓은 기업 운영 스택을 한 번에 제공하느냐로 이동했음을 보여줍니다. 특히 데이터, 보안, 네트워크, 업무 협업툴까지 하나의 패키지로 묶는 전략은 CIO와 플랫폼 조직에 더 설득력 있게 작동할 수 있습니다. 경쟁사들도 에이전트 플랫폼 서사를 더 구체적인 운영 제품으로 바꿔야 하는 압박을 받을 가능성이 큽니다.

왜 중요한지: 이제 기업 AI 경쟁은 ‘가장 똑똑한 모델’보다 ‘가장 빨리 현업에 꽂히는 스택’을 누가 갖췄는지가 더 중요해지고 있습니다.

2. Google, 8세대 TPU ‘TPU 8t·8i’ 공개… 학습과 추론을 분리 최적화

핵심 요약

Google은 Cloud Next에서 8세대 TPU를 발표하며 학습용 TPU 8t와 저지연 추론용 TPU 8i라는 두 가지 아키텍처를 제시했습니다. 회사 설명에 따르면 두 칩은 대규모 모델 학습, 에이전트 개발, 대량 추론 워크로드를 각각 더 효율적으로 처리하도록 설계됐습니다. Google은 두 제품이 자사 슈퍼컴퓨터 구성의 핵심이 되며, 올해 안에 순차적으로 제공될 예정이라고 밝혔습니다. 메시지는 단순 성능 자랑보다 ‘에이전트 시대에 맞는 전용 인프라’입니다.

배경·업계 영향

AI 인프라 병목이 계속되는 상황에서 학습과 추론을 각각 따로 최적화하는 접근은 비용 구조와 지연시간 관리에 직접적인 영향을 줍니다. 특히 에이전트형 서비스는 짧은 응답 지연과 반복 호출이 중요해서, 추론 특화 칩의 중요성이 더 커질 수 있습니다. 이는 엔비디아 중심 구도에 맞서 클라우드 사업자들이 자체 실리콘 전략을 더 강하게 밀어붙이고 있음을 보여줍니다.

왜 중요한지: 모델 경쟁의 뒤쪽에서는 결국 누가 더 싸고 빠르게 추론을 돌리느냐가 수익성과 확장성을 결정합니다.

3. Google Workspace, ‘Workspace Intelligence’로 이메일·문서·채팅 맥락을 에이전트용 컨텍스트로 묶기 시작

핵심 요약

Google Workspace는 4월 말 발표한 Workspace Intelligence를 통해 Gmail, Docs, Slides, Drive, Chat 전반의 맥락을 하나의 실시간 이해 레이어로 묶겠다고 밝혔습니다. Google은 이 기능이 사용자의 프로젝트, 협업자, 조직 지식을 함께 파악해 더 개인화된 초안 작성, 우선순위 파악, 파일 탐색, 일정 조정 같은 작업을 지원한다고 설명했습니다. 특히 Chat 안에서 Gemini를 호출해 브리핑, 문서 생성, 미팅 일정 조정 같은 작업을 수행하는 흐름을 전면에 내세웠습니다. 단순 보조 기능이 아니라 ‘업무용 명령 레이어’를 만들겠다는 방향이 선명합니다.

배경·업계 영향

기업 생산성 툴 경쟁은 이제 기능 목록보다 누가 더 많은 업무 맥락을 안전하게 연결하느냐에 달려 있습니다. Workspace Intelligence가 자리 잡으면 문서 작성 도구, 이메일, 협업툴의 경계는 더 흐려지고, 업무용 AI는 점점 독립된 앱이 아니라 기본 인터페이스가 될 가능성이 큽니다. 동시에 데이터 거버넌스와 권한 제어가 실제 도입 속도를 가르는 핵심 변수가 될 것입니다.

왜 중요한지: 기업용 AI의 승부처는 ‘잘 대답하는 챗봇’이 아니라 조직 맥락을 얼마나 정확히 읽고 실행하느냐입니다.

4. Google Cloud, 관리형 MCP 서버로 에이전트의 ‘툴 연결’을 기업 서비스로 제품화

핵심 요약

Google Cloud는 Google-managed MCP servers를 통해 AI 에이전트가 Maps, BigQuery, GKE, Cloud Run 등 Google 서비스와 안전하게 연결되도록 지원한다고 설명했습니다. 회사는 로컬 오픈소스 MCP 서버가 실험 단계에서는 유용하지만, 프로덕션 환경에서는 확장성·보안·운영 복잡도가 문제라고 짚었습니다. 이에 따라 Google이 직접 호스팅·확장·보안을 맡는 관리형 엔드포인트와 감사 로그, IAM, VPC-SC, Model Armor 같은 통합 보안 기능을 전면에 내세웠습니다. 예시로는 실시간 위치·날씨 정보를 받아 도시 이미지를 생성하는 에이전트 데모를 제시했습니다.

배경·업계 영향

MCP는 에이전트 업계에서 사실상 표준 인터페이스로 빠르게 굳어지고 있는데, 이제 경쟁 포인트는 표준 자체보다 누가 더 안정적인 운영형 엔드포인트를 제공하느냐로 옮겨가고 있습니다. 관리형 MCP는 기업이 에이전트 실험을 파일럿에서 운영 단계로 끌어올릴 때 가장 큰 장애물인 인증, 감사, 확장성을 줄여줄 수 있습니다. 다른 클라우드와 플랫폼 사업자도 유사한 ‘관리형 툴 연결 계층’을 서둘러 내놓을 가능성이 큽니다.

왜 중요한지: 에이전트가 실제 일을 하려면 결국 외부 도구를 안전하게 호출해야 하고, 그 연결층이 새 인프라 전쟁터가 되고 있습니다.

5. GitHub Copilot, 개인 요금제에 flex allotment와 Max 플랜 추가

핵심 요약

GitHub는 5월 12일 Copilot 개인 요금제를 6월 1일부터 조정한다고 발표했습니다. Pro와 Pro+에는 기본 크레딧 외에 변동형 추가 사용량인 flex allotment가 붙고, 고사용량 사용자를 위한 월 100달러의 Max 플랜도 새로 도입됩니다. GitHub 설명에 따르면 Pro는 총 15달러 상당, Pro+는 총 70달러 상당, Max는 총 200달러 상당의 포함 사용량을 제공합니다. IDE, github.com, CLI 전반에서 같은 요율로 차감되며, 코드 자동완성과 Next Edit 제안은 계속 무제한으로 유지됩니다.

배경·업계 영향

에이전트형 코딩 사용이 길어지고 무거워질수록 기존 정액제만으로는 수익성과 가격 신호를 맞추기 어려워집니다. GitHub의 이번 조정은 개발자 AI 시장이 성능 경쟁과 함께 비용 예측 가능성, 헤비 유저 분리, 사용량 시각화 경쟁으로 들어가고 있음을 보여줍니다. 다른 코딩 AI 업체들도 비슷한 단계형 가격 전략을 더 자주 손볼 가능성이 큽니다.

왜 중요한지: 코딩 AI 시장에서는 이제 모델 품질만큼 ‘얼마나 쓰게 될지, 얼마가 나올지’가 실제 구매 결정을 좌우합니다.

6. Google Cloud, ‘Agentic Data Cloud’로 데이터 플랫폼을 실행형 시스템으로 재정의

핵심 요약

Google Cloud는 Agentic Data Cloud를 소개하며 기존 데이터 플랫폼을 단순 저장소가 아니라 에이전트가 추론하고 행동할 수 있는 ‘System of Action’으로 확장하겠다고 밝혔습니다. 발표 내용에는 Knowledge Catalog, Deep Research Agent 미리보기, Google Cloud Data Agent Kit, 그리고 크로스클라우드 레이크하우스 전략이 포함됐습니다. Google은 Vodafone, American Express, Virgin Voyages 사례를 제시하며 대규모 에이전트 운영에 필요한 맥락, 거버넌스, 검색·권한 체계를 통합하려는 의도를 분명히 했습니다. 특히 개발자가 VS Code, Gemini CLI, Codex, Claude Code 같은 환경에서 바로 데이터 작업을 오케스트레이션할 수 있다는 점을 강조했습니다.

배경·업계 영향

데이터 플랫폼 시장도 이제 BI와 쿼리 중심에서, 에이전트가 실제로 조직 데이터를 읽고 행동하는 실행 계층으로 옮겨가고 있습니다. 이는 카탈로그, 검색, 권한, 파이프라인 자동화가 모두 AI 추론 품질의 일부가 된다는 뜻입니다. 데이터 클라우드 업체들은 ‘분석 도구’가 아니라 ‘에이전트용 컨텍스트 엔진’으로 포지셔닝을 바꾸게 될 가능성이 큽니다.

왜 중요한지: 좋은 모델만으로는 부족하고, 결국 기업 데이터가 실행 가능한 맥락으로 바뀌어야 에이전트가 돈 되는 일을 할 수 있습니다.
