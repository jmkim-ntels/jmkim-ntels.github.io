1. OpenAI, 고위험 사용자용 ‘Advanced Account Security’ 도입

핵심 요약

OpenAI는 ChatGPT 계정용 opt-in 보안 모드인 Advanced Account Security를 공개했습니다. 이 설정을 켜면 패스키나 물리 보안키 기반 로그인으로 전환되고, 이메일·SMS 기반 계정 복구는 비활성화됩니다. OpenAI는 짧은 세션 유지, 로그인 알림, 활성 세션 관리 강화도 함께 제공한다고 설명했습니다. 또한 해당 보호는 ChatGPT뿐 아니라 같은 로그인 체계를 쓰는 Codex에도 적용됩니다.

배경·업계 영향

AI 계정은 이제 단순한 채팅 이력 저장소가 아니라 코드, 문서, 업무 맥락, 연결된 도구 접근권까지 담는 허브가 되고 있습니다. 그래서 계정 탈취 리스크는 메일이나 협업툴 수준으로 커졌고, 플랫폼 사업자도 보안 기능을 프리미엄 인프라처럼 다루기 시작했습니다. 특히 보안 민감 직군을 직접 겨냥한 점은 AI 서비스가 공공·정치·연구 업무까지 깊게 들어갔다는 신호입니다.

왜 중요한지: AI 서비스 경쟁에서 계정 보안이 이제 부가 기능이 아니라 핵심 제품 경쟁력이 됐습니다.

2. OpenAI, AWS에서 모델·Codex·Managed Agents 제한 프리뷰 시작

핵심 요약

OpenAI는 AWS와의 전략적 파트너십 확대를 발표하며 OpenAI 모델, Codex, Amazon Bedrock Managed Agents powered by OpenAI를 제한 프리뷰로 제공한다고 밝혔습니다. 발표문에 따르면 AWS 고객은 기존 보안·컴플라이언스·조달 체계 안에서 GPT-5.5 같은 최신 모델을 쓸 수 있게 됩니다. Codex도 Bedrock API를 통해 CLI, 데스크톱 앱, VS Code 확장 등에서 연결할 수 있도록 열립니다. 핵심은 OpenAI 기능이 특정 플랫폼 밖으로 더 넓게 유통되며 기업 도입 장벽을 낮추는 데 있습니다.

배경·업계 영향

대기업은 좋은 모델만으로 움직이지 않고, 기존 클라우드 정책과 결제 구조 안에서 바로 붙는지를 더 중요하게 봅니다. 이번 발표는 모델 사업자와 클라우드 사업자가 경쟁하면서도 동시에 유통 파트너가 되는 구조를 더 선명하게 보여줍니다. 멀티클라우드 AI 전략이 표준이 될수록 이런 협력은 더 자주 나올 가능성이 큽니다.

왜 중요한지: 기업 시장에선 모델 성능 못지않게 “지금 쓰는 클라우드에 바로 얹히는가”가 승부처입니다.

3. Anthropic·Amazon, Claude용 신규 컴퓨트 최대 5GW 확보 계약 발표

핵심 요약

Anthropic은 Amazon과의 새 계약으로 Claude 학습·배포용 최대 5기가와트 규모의 컴퓨트 용량을 확보한다고 발표했습니다. 회사는 상반기 중 추가 Trainium2 용량이 들어오고, 2026년 말까지 Trainium2·Trainium3 기반 nearly 1GW가 가동될 예정이라고 설명했습니다. 동시에 Claude Platform on AWS를 같은 계정, 같은 통제 체계, 같은 청구 흐름 안에서 제공하는 방향도 예고했습니다. 발표문에는 Amazon이 즉시 50억 달러를 추가 투자하고, 향후 최대 200억 달러를 더 투자할 수 있다는 내용도 포함됐습니다.

배경·업계 영향

프런티어 모델 경쟁은 이제 알고리즘뿐 아니라 전력, 칩, 장기 조달 계약을 얼마나 안정적으로 확보하느냐의 싸움이 됐습니다. 특히 커스텀 AI 칩인 Trainium 계열이 실제 대규모 상용 서비스에 얼마나 깊게 들어가는지가 중요한 신호가 되고 있습니다. 이번 발표는 클라우드와 모델 기업의 관계가 단순 고객·공급자를 넘어 장기 공동 인프라 파트너십으로 굳어지고 있음을 보여줍니다.

왜 중요한지: 차세대 AI 경쟁의 숨은 본체는 모델 발표보다 전력과 컴퓨트 공급망입니다.

4. GitHub, Copilot를 6월부터 usage-based billing으로 전환

핵심 요약

GitHub는 2026년 6월 1일부터 모든 Copilot 플랜이 GitHub AI Credits 기반 과금으로 전환된다고 발표했습니다. 기존의 premium request 단위 대신 입력·출력·캐시 토큰 사용량에 따라 크레딧이 차감되는 구조입니다. 기본 월 구독료는 유지되지만, 포함 사용량을 넘기면 추가 소비를 직접 통제하거나 더 구매하는 방식으로 바뀝니다. GitHub는 에이전트형 장시간 코딩 세션이 늘어나면서 기존 과금 모델이 지속 가능하지 않았다고 설명했습니다.

배경·업계 영향

AI 코딩 도구가 짧은 자동완성에서 장시간 자율 작업으로 이동할수록, 정액제는 공급자에게 불리해지고 헤비 유저 제한이 늘어날 수밖에 없습니다. GitHub의 이번 전환은 다른 AI 개발 도구 기업에도 가격 재설계 압박을 줄 가능성이 큽니다. 동시에 기업 고객 입장에서는 예산 통제와 비용 가시성이 더 중요해질 전망입니다.

왜 중요한지: AI 코딩 도구 시장이 이제 기능 경쟁을 넘어 수익 모델 재편 단계로 들어갔습니다.

5. GitHub, 치명적 git push 원격 코드 실행 취약점 대응 경과 공개

핵심 요약

GitHub는 자사 git push 처리 파이프라인에서 발견된 치명적 원격 코드 실행 취약점 대응 과정을 상세히 공개했습니다. 발표에 따르면 연구자 제보를 받은 뒤 40분 안에 재현과 심각도 확인을 마쳤고, 2시간이 채 안 돼 github.com에 수정 배포와 포렌식 조사를 시작했습니다. 취약점은 user-supplied push option 값이 내부 메타데이터에 충분히 sanitize되지 않아 신뢰된 내부 필드처럼 해석될 수 있었던 문제였습니다. GitHub는 조사 결과 연구자의 테스트 외 악용 흔적은 없었고, GHES 고객에게는 관련 패치 버전으로 즉시 업그레이드할 것을 권고했습니다.

배경·업계 영향

개발자 플랫폼은 소스코드 저장소이면서 동시에 소프트웨어 공급망의 핵심 인프라라, 이런 취약점은 영향 범위가 매우 넓을 수 있습니다. 이번 사례는 입력 검증 같은 기본 보안 원칙과 함께, 원래 없어야 할 코드 경로를 배포 이미지에서 제거하는 방어 심층화의 중요성을 다시 보여줬습니다. AI 도구 확산과 별개로 개발 인프라 보안 자체가 계속 큰 이슈로 남아 있다는 뜻입니다.

왜 중요한지: 코드 협업 플랫폼의 취약점은 곧 전체 소프트웨어 공급망 리스크로 번질 수 있습니다.
